      • Mkdocs로 Github Pages 구축

    이 페이지에서는 Obsidian에서 작성한 .md 파일의 문서를 MkDocs를 통해 html로 변환하여 github.io에 올리는 방법에 대해 정리한다. 사용하는 환경은 윈도우 환경에서의 Obsidian 작성 및 WSL(Ubuntu-24.04)에서의 MkDocs를 가정한다.

    Obsidian & MkDocs?

    Obsidian은 Markdown 파일을 기반으로 한 Personal Knowledge Management (PKM) 도구이다.
    로컬 파일 시스템에 저장된 .md 파일을 그대로 사용한다. 특히 연구 노트, 수업 정리, 기술 메모처럼 장기적으로 축적·확장되는 지식 관리에 매우 적합하다.

    MkDocs는 Markdown(.md) 파일로 문서를 작성하면, 이를 자동으로 정적 사이트 형태로 만들어주는 도구이다.
    주로 프로젝트 문서를 깔끔한 네비게이션/검색/목차와 함께 보여주기 좋고, GitHub Pages 같은 곳에 쉽게 배포할 수 있다는 장점이 있다.

    즉, 두 도구는 같은 Markdown 파일을 사용하지만 목적이 다르다.

    • Obsidian은 개인적인 사고·연구·정리를 위한 도구이고
    • MkDocs는 그중 필요한 내용을 선별해 외부에 공유 가능한 문서 사이트_로 변환하는 역할을 한다.

    이 둘을 함께 사용하면, Obsidian에서 자유롭게 연구·정리 → MkDocs로 정제된 문서만 공개라는 워크플로우를 구성할 수 있어, 연구·프로젝트 문서화에 매우 효율적인 조합이 된다.

    1. MkDocs 설치

    1.1 pipx 설치

    sudo apt update
sudo apt install pipx

    PATH 설정 (처음 한 번): 

    pipx ensurepath
source ~/.bashrc

    설치 확인:
    pipx --version

    1.2 MkDocs 설치

    pipx install mkdocs
pipx inject mkdocs mkdocs-material

    설치 확인:
    mkdocs --version

    2. MkDocs 설정

    Obsidian에서 생성한 vault가 있는 폴더 위치로 이동한다. 

    cd ~/mnt/c/Users/dongh/Documents/Obsidian\ Vault  
mkdocs new .

    → 생성되는 docs/ 폴더가 github.io로 나갈 영역 → 편의를 위해 docs_build로 변경해주었다.

    2.1 목표 폴더 구조

    폴더

    • assets_src/ : 커스텀 CSS/JS 원본(Obsidian과 분리)
    • docs_build/ : MkDocs가 읽는 문서 루트(= docs_dir)
    • notes/ : Obsidian에서 실제로 작성하는 원본 노트
    • scripts/ : 자동 링크/네비 생성 파이썬 스크립트
    • site/ : mkdocs build 결과물(로컬 빌드용, gh-deploy가 쓰기도 함)

    파일

    • mkdocs.yml : MkDocs 사이트 설정 파일(테마, 문서 폴더, 확장, CSS/JS, nav 등)
    • serve.sh : sync_links.py로 notes→docs_build 동기화, mkdocs serve로 로컬 미리보기 실행
    • deploy.sh : sync_links.py로 동기화, mkdocs gh-deploy로 GitHub Pages에 배포

    Obsidian에서의 설정

    • Meta bind (Obsidian plugin)를 통해, 메타 데이터를 만들어 준다.
    • 이를 통해 github에 업로드할 때, private, public으로 할지 업로드하지 말지를 정한다.
    • scripts/내부에 python 코드로 notes 폴더를 docs_build로 링크.
    • 마찬가지로 내부파일들을 통해 mkdocs.yml 자동 작성.
    • .sh를 통해 자동화 추가

    2.2 로컬에서 미리보기

    mkdocs serve → ./serve.sh 로도 가능

    브라우저에서: http://127.0.0.1:8000

    2.3 Material 테마 적용

    site_name: Donghoo Docs
site_url: https://donghoo03.github.io/
docs_dir: docs_build

theme:
  name: material

extra_css:
  - assets/stylesheets/extra.css

extra_javascript:
  - assets/javascripts/marquee.js
  - assets/javascripts/mathjax-config.js
  - https://cdn.jsdelivr.net/npm/mathjax@3/es5/tex-mml-chtml.js

markdown_extensions:
  - pymdownx.arithmatex:
      generic: true
  - pymdownx.superfences
  - pymdownx.details
  - admonition
    • mkdocs.yml 내부에 필요한 내용 추가. (필요에 따라 수정)
    • nav는 scripts로 자동화.

    3.2 Upload

    mkdocs gh-deploy → `./deploy.sh 로 자동화 (스크립트 실행 후 deploy)

    • Markdown 문서를 HTML로 빌드하여 gh-pages branch에 자동 업로드
    • GitHub Pages에 즉시 반영됨

    이미 한 번이라도 정상적으로 mkdocs gh-deploy가 성공했다면 → 앞으로는 그냥 mkdocs gh-deploy만 치면 됨

    아직 GitHub repo / remote / 인증이 안 되어 있으면 → 초기 1회 세팅 필요

    로컬 프로젝트 폴더로 이동 후:

    Git 초기화 (처음 1회) 

    git init 
git branch -M main

    GitHub 레포와 연결 (remote 설정) 

    git remote add origin https://github.com/donghoo03/donghoo03.github.io.git
git remote -v

    로그인 정보 입력하면 github.io 레포에 gh-pages branch가 생성된다.

    페이지로 들어가면, Mkdocs로 로컬에서 확인한 것과 동일하게 업로드 되어있다. →만약 업로드 되어있지 않다면 F5로 refresh.
